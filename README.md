# Sleep Planner

Небольшой сервис на **FastAPI** для студента: оценивает время отбоя и подъёма по циклам, недосып, социальный джетлаг, время отсечки кофе и план сдвига режима.

Сервис ничего не сохраняет и не обращается к внешним API. Входные времена относятся к условным суткам: даты, часовые пояса и перевод часов не моделируются. Интерактивно попробовать API можно в `/docs` после локального запуска.

> **Оценка по средним значениям, не медицинская рекомендация.** Расчёт не измеряет реальные стадии сна и не гарантирует пробуждение в конце физиологического цикла.

**Автор:** Александр Крючатов (Alex Kryuchatov). Поведение сервиса проверяется тестами из `test_app.py`.

## Возможности

- **Время отбоя** — варианты времени сна для заданного подъёма и числа циклов.
- **Время подъёма** — варианты пробуждения для заданного времени отбоя.
- **Недосып** — расчёт за 1–14 ночей, средняя продолжительность и короткие ночи.
- **Социальный джетлаг** — разница середин сна в рабочие и свободные дни.
- **Последний кофе** — время отсечки относительно планируемого отбоя.
- **План сдвига режима** — пошаговый переход к целевому времени отбоя.

## Быстрый запуск на macOS

Нужны Python **3.12**, терминал zsh и интернет для установки пакетов. Для клонирования репозитория нужен Git.

### 1. Скачайте проект

Склонируйте репозиторий или выберите на GitHub **Code → Download ZIP** и распакуйте архив. Откройте терминал в папке, где лежит `app_final.py`: все команды ниже выполняются из неё.

### 2. Подготовьте окружение и запустите сервер

Если `python3` другой версии, используйте установленный `python3.12` вместо `python3` при создании окружения.

```zsh
python3 --version
python3 -c 'import sys; assert sys.version_info[:2] == (3, 12), "Нужен Python 3.12"'
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
python -m pytest -v
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000 --no-access-log
```

Ожидается `127 passed` и затем работающий сервер; он занимает текущий терминал. Для остановки нажмите **Ctrl+C** в терминале сервера. Не используйте Ctrl+Z: он приостанавливает процесс.

### 3. Попробуйте приложение

1. Откройте в браузере [интерактивную документацию API](http://127.0.0.1:8000/docs).
2. Разверните **GET /sleep/bedtime** и нажмите **Try it out**.
3. Введите `07:00` в поле `wake`, остальные параметры оставьте без изменений и нажмите **Execute**.
4. Посмотрите JSON в разделе **Response body**. При исходных настройках поле `recommended` содержит `23:15`.

Таким же образом можно попробовать остальные маршруты. Готовые команды `curl` и ожидаемые ответы приведены в разделе [API и ожидаемые ответы](#api-и-ожидаемые-ответы). Отдельной страницы-калькулятора нет: интерфейс для проверки API — `/docs`.

### 4. Проверьте окружение

Установка зафиксирована через `pip freeze` в чистом venv Python **3.12.14**. Прямые runtime-зависимости: FastAPI **0.153.0**, Uvicorn **0.54.0**, python-dotenv **1.2.4**. Прямые dev-зависимости: pytest **9.1.1**, httpx **0.28.1**. Оба requirements фиксируют также установленные транзитивные зависимости. Например, `opentelemetry-api` установлена самим FastAPI; экспорт телеметрии проект не настраивает. Это не дополнительный сервис.

```zsh
python -m pip freeze
python -m pip check
```

Ожидается список закреплённых версий и `No broken requirements found.` Не перезаписывайте `requirements.txt` полным freeze из личного общего окружения: это смешает runtime и dev. При обновлении сначала проверяйте чистую установку и тесты.

При запуске тестов Starlette предупреждает, что поддержка `httpx` в TestClient устаревает в пользу `httpx2`. На результат это не влияет, тесты проходят. `httpx` оставлен, потому что он нужен для тестов.

Явный query-параметр `cycle_minutes=90` имеет приоритет над default из окружения. После проверки верните 90 и перезапустите. ## API и ожидаемые ответы

Все собственные маршруты работают через GET и отвечают JSON. `/docs` — встроенная HTML-документация FastAPI. Время на входе `Ч:ММ` или `ЧЧ:ММ`, время суток на выходе всегда `ЧЧ:ММ`. `jetlag` означает продолжительность, поэтому `2:45`, а не время суток `02:45`.

Время проверяется регулярным выражением: `^([01]?[0-9]|2[0-3]):[0-5][0-9]$`. Список ночей: `^\d{1,2}(\.\d{1,2})?(,\d{1,2}(\.\d{1,2})?){0,13}$`.

| Маршрут | Обязательные параметры | Необязательные параметры |
|---|---|---|
| `/`, `/health`, `/version` | Нет | Нет |
| `/sleep/bedtime` | `wake` | `cycles` 1-8, `cycle_minutes` 70-110, `latency` 0-60 |
| `/sleep/wake-time` | `bedtime` | Те же параметры циклов |
| `/sleep/debt` | `nights`: 1-14 значений через запятую | `need` 4-12 |
| `/sleep/social-jetlag` | `work_bed`, `work_wake`, `free_bed`, `free_wake` | Нет |
| `/sleep/caffeine` | `bedtime` | `hours_before` 3-12 |
| `/sleep/shift-plan` | `current`, `target` | `step` 5-60, default 15 |

Примеры ниже рассчитаны для неизменённого `.env.example`. Сохраните кавычки вокруг URL: `&` и `?` имеют специальный смысл в zsh.

## Ошибки API

```zsh
curl -i "http://127.0.0.1:8000/sleep/bedtime?wake=24:00"
curl -i "http://127.0.0.1:8000/sleep/debt?nights=17"
curl -i "http://127.0.0.1:8000/sleep/social-jetlag?work_bed=07:00&work_wake=07:00&free_bed=02:00&free_wake=11:00"
curl -i "http://127.0.0.1:8000/sleep/shift-plan?current=00:00&target=12:00&step=5"
curl -i "http://127.0.0.1:8000/unknown"
```

В том же порядке ожидается:

1. **422**: FastAPI `detail` со списком ошибок; `loc=["query","wake"]`.
2. **400**: `{"detail":"Ночь не может длиться больше 16 часов"}`.
3. **400**: `{"detail":"Продолжительность сна должна быть от 1 до 16 часов"}`.
4. **400**: `{"detail":"Слишком долгий переход, увеличьте step"}`.
5. **404**: `{"detail":"Not Found"}`.

Отсутствующий обязательный параметр, неверный тип, формат или диапазон дают **422** через `Query`. Формально допустимые, но бессмысленные данные дают **400** через `HTTPException`. Список `7,5,6` означает три ночи. Нулевой сон в `/sleep/debt` допустим: это ночь без сна; одинаковые bed/wake в джетлаге означают недопустимую нулевую продолжительность.

## Формулы и границы модели

- `minutes = hours * 60 + minutes_part`; любое время суток нормализуется `% 1440`. Длительности и количества дней сами по себе не являются временем суток.
- `sleep_minutes = cycles * cycle_minutes`. Отбой: `(wake - sleep_minutes - latency) % 1440`. Подъём: `(bedtime + latency + sleep_minutes) % 1440`. Без `cycles` выдаются 6/5/4 цикла для отбоя и 4/5/6 для подъёма. Порядок относителен к выбранному сну; строки часов через полночь не сортируются лексикографически.
- Выбирается минимальное число циклов из предложенных, покрывающее `SLEEP_GOAL_HOURS * 60`. Если его нет, `recommended=null` и предупреждение с действующим порогом. Проверка порога использует точные минуты до округления часов.
- Недосып: `max(0, need * N - sum(nights))`; избыток: `max(0, sum(nights) - need * N)`; среднее: `sum(nights) / N`. `short_nights` сравнивает каждую ночь с `SLEEP_GOAL_HOURS`, независимо от `need`. Это арифметическая модель, избыток не означает доказанную физиологическую компенсацию недосыпа.
- Продолжительность интервала сна: `(wake - bed) % 1440`, допустимо 60-960 мин включительно. Середина: `(bed + duration // 2) % 1440`. Джетлаг: `min(abs(mid_free-mid_work), 1440-abs(mid_free-mid_work))`. `over_one_hour` означает **не менее** 60 минут, это граница модели, а не клинический порог.
- Кофе: `(bedtime - rounded_minutes(hours_before * 60)) % 1440`. При дробной минуте применяется `Decimal` и `ROUND_HALF_UP` до целой минуты; при `3.125` ч получается 188 мин. Так минуты всегда получаются целыми. В ответе часы округлены до двух знаков; сама формула использует исходное значение.
- План: кратчайший круговой путь; при равенстве выбирается `earlier`. `days = ceil(diff / step)`, целочисленно `(diff + step - 1) // step`. Последний шаг ограничен остатком. Если выходит больше 60 дней, ответ 400. При совпадении режимов `direction="earlier"`, 0 дней и пустой план.
- Часы считаются через `Decimal`, вывод округляется до 2 знаков `ROUND_HALF_UP`. JSON-число `9.0` может отображаться клиентом как `9`: это не потеря точности. Середина нечётной длительности округляется вниз.

### Источники

Материалы, использованные в описании модели:

| Основа | Применение | Источник |
|---|---|---|
| Ф1: средний цикл около 90 мин, модель допускает 70-110 | `cycle_minutes` | [Sleep cycle](https://en.wikipedia.org/wiki/Sleep_cycle) |
| Ф2: рекомендация AASM/SRS взрослым 18-60 лет: 7 и более часов | Порог по умолчанию 7, не медицинская верхняя граница | [AASM](https://aasm.org/seven-or-more-hours-of-sleep-per-night-a-health-necessity-for-adults/) |
| Ф3: исследование Drake и соавт., 2013, 400 мг за 6 часов | Default отсечки 6 ч; при другом параметре `basis` остаётся описанием исходного исследования | [AASM о кофеине](https://aasm.org/late-afternoon-and-early-evening-caffeine-can-disrupt-sleep-at-night/) |
| Ф4: различие середин сна в рабочие и свободные дни | Круговое расстояние, без диагноза | [Social jetlag](https://en.wikipedia.org/wiki/Social_jetlag) |

15 минут на засыпание и 15 минут в день для сдвига — допущения модели, а не медицинские нормы. Диапазоны валидации тоже границы модели, а не медицинские ограничения. Период полувыведения кофеина не используется.

Поле `note` во всех ответах одинаковое. Пояснения к джетлагу и плану сдвига вынесены в отдельное поле `context`.

## Логи

Логгер `sleep_planner`, формат `%(asctime)s %(levelname)s %(name)s %(message)s`, stderr. Уровень меняется через `LOG_LEVEL`. В событиях нет времени сна, query-строк, списка ночей и полного окружения. Временная метка слева показывает время события на сервере, а не пользовательский ввод.

INFO: `service_started version=1.0.0`, `service_stopped`, `bedtime_calculated`, `wake_time_calculated`, `debt_calculated nights=N`, `social_jetlag_calculated`, `caffeine_calculated`, `shift_plan_calculated days=N`. WARNING для каждого 400: `night_too_long`, `invalid_sleep_duration`, `shift_too_long`. Если `LOG_LEVEL` выше WARNING, порог закономерно скрывает эти записи, хотя вызов WARNING выполнен.

```zsh
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000 --no-access-log > service.log 2>&1
```

Во втором терминале, в той же папке:

```zsh
tail -n 30 service.log
tail -f service.log
```

`--no-access-log` обязателен для этих команд: обычный access-log Uvicorn содержит URL с пользовательским временем. `>` заменяет прежний файл; используйте `>> service.log 2>&1`, если нужно дописать. `*.log` игнорируется Git. Ctrl+C в просмотре прекращает только `tail`, а не сервер в другом терминале.

## CI и скачиваемый artifact

`.github/workflows/ci.yml` запускается на **push и pull_request** без фильтра веток. `permissions: contents: read`. Job `test`: checkout → Python 3.12 с pip cache → установка обоих requirements → `python -m pytest -v`. Job `package` с `needs: test` получает код заново, собирает `dist/` и вызывает upload-artifact с `if-no-files-found: error`, сроком 30 дней.

Используются `actions/checkout@v7`, `actions/setup-python@v7` и `actions/upload-artifact@v7`.

`dist/` собирается по явному списку: приложение, тесты, оба requirements, README, `.gitignore`, CI, smoke-скрипт, безопасный `.env.example`. Рядом кладётся копия `env.example` с тем же содержимым — на случай, если файл ожидается под таким именем. `include-hidden-files: true` сохраняет `.env.example` и `.github`, а явное копирование не допускает настоящий `.env`, `.git` и `.venv`.

На странице конкретного зелёного run откройте раздел **Artifacts**, скачайте `sleep-planner`. Распакуйте в отдельную пустую папку: внутри скачанной поставки сразу лежит `app_final.py`, без внешней папки `sleep-planner/`.

```zsh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
python -m pytest -v
python scripts/smoke_test.py
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000 --no-access-log
```

В artifact нет Git-истории: для запуска и тестов она не нужна. README, тесты и dev-зависимости включены, поэтому установка из artifact не требует отсутствующих файлов.

Схемы: **клиент → Uvicorn → FastAPI → расчёт → JSON**; **git push / pull request → Actions → pytest → artifact**. Окружение задаёт параметры при создании приложения; события уходят в stderr. Ни GitHub-репозиторий, ни artifact сами по себе не являются постоянно работающим сервисом.

## Частые проблемы на Mac

| Симптом | Проверка | Исправление |
|---|---|---|
| `Address already in use` | `lsof -nP -iTCP:8000 -sTCP:LISTEN` | Найдите свой старый Uvicorn и остановите Ctrl+C; чужой процесс не трогайте. Либо порт 8001 и тот же порт во всех URL |
| 404 | `curl -i http://127.0.0.1:8000/version`, путь в `/docs` | Проверьте путь и `app_final:app`, а не переустанавливайте зависимости |
| 422 | `detail`, `loc`, query-параметры | Исправьте формат, тип, обязательные параметры и диапазон |
| 400 | `detail` и WARNING | Исправьте содержательный вход: ночь >16 ч, интервал вне 1-16 ч, план >60 дней |
| `ModuleNotFoundError` | `which python`, `python -m pip --version` | `source .venv/bin/activate`, затем установите оба requirements |
| Изменённый `.env` не влияет | Старый процесс, экспорт, явный query | Остановите сервер; `unset CYCLE_MINUTES` при старом export; перезапустите без переопределяющего query |
| `ValueError` при запуске | Последняя строка с именем настройки | Исправьте настройку по таблице; pytest изолирован от личного `.env` и сам по себе не доказывает его правильность |
| `Permission denied` | `whoami`, `ls -ld . .venv`, `ls -l app_final.py` | Работайте в своей папке. `source`, а не исполнение activate; для исходника достаточно `python`, право x ему не нужно |
| Кажется, Uvicorn завис | `/health`, наличие слушателя | Ожидание запросов нормально. Для остановки Ctrl+C; при необходимости проверьте конкретный свой PID перед `kill` |
| Локально зелёный, CI красный | SHA run, шаг установки/pytest | Сверьте зафиксированные файлы, зависимости, регистр путей и содержание ошибки |
